# Claim ledger

Every claim this design leans on is either **opened at its primary source** (`verified`, with a
URL and the date it was opened) or **deleted** (`withdrawn`, with a `dropped:` or `replaced:` note).
There is no third state, and the gate that enforces it is `tests/test_verification_table.py`, which
parses this file. A green run means the ledger is internally consistent; it does not mean a row is
true — it means the row names a source that was opened on the date recorded and, for `withdrawn`
rows, says what became of the claim.

Rules this ledger holds itself to, copied from the design's §17:

* A `verified` row carries a real URL and a date. "Partially confirmed from a search snippet" is not
  `verified`.
* A row whose source cannot be opened is `withdrawn`, with `dropped:` (the claim is gone) or
  `replaced:` (a corrected claim takes its place).
* A `withdrawn` row whose claim still lives in the spec is a bug in the spec, not in this file.
  §1, §5.4, §5.5, §12, §13, §14 and §17 of
  `docs/superpowers/specs/2026-09-29-certified-decision-gate-design.md` were edited in the same
  commit as the rows below that forced each change.
* Volatile numbers (star counts) are recorded as dated observations, never as rounded adjectives.

Rows 1–10 are the spec's `[local]` rows, re-opened here against the upstream tag rather than the
vendored directory: the last row of the table records the blob-hash check that makes those
permalinks and the local tree the same bytes.

## What is still owed

* `guard-preset-overlap` is the only load-bearing number in the design that rests on a single
  unpublished observer. Task 3 must re-derive it from committed records or §5.5's anchor case has to
  be replaced by a different refusal example.
* §12's three "none found" rows are tasks, not facts: the systematic searches are pre-registered
  before they run, and `ordinal-cp-literature-size` is the warning that a single arXiv query already
  produced six papers where the design remembered four.
* `verdict-automation-guarantee`, `open-medical-jev-auto-release` and `poorjev-conformal-abstention` are
  read from their READMEs and benchmark tables, not from papers. §1's narrowing rests on them, so the
  head-to-head that decides whether the remaining delta is real (conditional bound, per-slice
  correction, envelope, ordinal one-sided family, contamination probe) is owed before §1 is quoted in
  any public text — and it belongs in the same §6.4 comparison harness that already decides the MAPIE
  question.
* The star count and the PyPI availability are dated observations; any text that re-quotes them
  re-opens them.
